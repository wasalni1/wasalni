# وصلني — الإصدار 4 (الأمان والسجلات الرقمية)

## ملفات المشروع (12 ملفاً، كلها في الصفحة الأولى للمستودع)
server.js · push.js · package.json · index.html · admin.html · audit.html · sw.js · icon.svg · icon-192.png · icon-512.png · README.md · test.js
لا يوجد `npm install` ولا مكتبات خارجية. تجربة محلية: `npm start` ثم `npm test`.

## 1) حفظ البيانات في Supabase (يُنصح به لأن Render المجاني يمسح الملفات)
1. أنشئ مشروعاً في supabase.com ثم افتح **SQL Editor** ونفّذ:
```sql
create table if not exists kv (k text primary key, v jsonb not null);
alter table kv enable row level security;
```
(تفعيل RLS بلا سياسات يمنع أي وصول من المتصفح، والخادم يدخل بمفتاحه السري فقط.)
2. من **Project Settings > API** انسخ **Project URL** ومفتاح **service_role** (أو secret key).
3. في Render > Environment أضف:
   - `SUPABASE_URL` = رابط المشروع
   - `SUPABASE_KEY` = المفتاح السري (لا تضعه في GitHub ولا في أي مكان عام)
4. بعد التشغيل ترى في لوحة الإدارة > نظرة عامة: «التخزين: Supabase». وإن كان الاتصال خاطئاً يتوقف الخادم عن العمل بدل أن يبدأ فارغاً.

## 2) استعادة كلمة السر بالبريد
بدون إعداد يظهر الرمز على الشاشة (وضع تجربة). لإرسال بريد فعلي: حساب في brevo.com، وتحقق من عنوان مرسل، ثم أضف
`BREVO_API_KEY` و`MAIL_FROM` (البريد الذي تحققت منه).

## 3) رسائل التأكيد SMS
أضف `SMS_WEBHOOK` برابط خدمة تستقبل `{phone,text}`، وإلا يظهر الرمز على الشاشة.

## 4) الإشعارات
تعمل Web Push تلقائياً: مفاتيحها تُولَّد وتُحفظ مع البيانات. المستخدم يضغط «تفعيل الإشعارات» مرة واحدة.
على الآيفون يلزم تثبيت التطبيق على الشاشة الرئيسية أولاً (iOS 16.4 فأعلى).

## الرصيد والبونص
شحن رصيد الراكب من الإدارة > الركاب والرصيد. الدفع من الرصيد يُخصم عند انتهاء الرحلة، ويُسجَّل للسائق «له عند المنصة»؛ والكاش تُسجَّل عمولته «عليه للمنصة». التسوية من الإدارة > السائقون.

## النشر
Render: Start Command `npm start`، Build Command فارغ. ملف APK: pwabuilder.com.

## السجلات الأمنية (Digital Audit Trail)
- صفحة مستقلة `/audit.html` بكلمة سر منفصلة. أضف في Render: `AUDIT_PASSWORD` (كلمة سر المدقق، تختلف عن الإدارة) و`AUDIT_KEY` (نص عشوائي طويل سري يُوقَّع به السجل؛ لا تغيّره بعد الآن وإلا يفشل التحقق من السجل القديم).
- يسجّل: التسجيل والدخول والخروج وفتح التطبيق (مع IP ونوع الجهاز والنظام وموقع GPS ودقته)، تعديل الاسم/البريد، تغيير كلمة السر، الرحلات (نقاط الانطلاق والوصول والمسار المخطط والمسار الفعلي للسائق والراكب)، المحادثات (بصمة النص والنص نفسه في الرحلة)، حركات المحفظة، وكل إجراء إداري.
- كل سجل مرتبط بما قبله بتوقيع (HMAC عند ضبط AUDIT_KEY): أي تعديل أو حذف يُكتشف من زر «تحقق من سلامة السجل».
- لا يوجد في أي واجهة حذف للرحلات أو السجلات، وأي محاولة تعديل أو حذف تُرفض وتُسجَّل. حذف المستخدم لحسابه يعطّل الحساب فقط ويُبقي كل السجلات.
- كل اطلاع أو بحث أو تصدير يُسجَّل بوقته وعنوان IP صاحبه. التقرير الكامل يُنزَّل من صفحة المدقق.
- لا يظهر أي من هذا للسائق أو العميل. الإدارة العادية لا تدخل صفحة المدقق إلا إن عرفت كلمتها.

## أمان التطبيق
رؤوس أمان وسياسة CSP، حد لعدد الطلبات، قفل الحساب 15 دقيقة بعد 5 محاولات خاطئة، كلمة سر 8 أحرف فأكثر مع تجزئة scrypt، رموز الجلسات تُحفظ مجزّأة وتُلغى عند تغيير كلمة السر، تحقق من كل مدخل وحجم الطلبات، دخول الإدارة برمز مؤقت. لا يوجد نظام محصّن بالكامل: فعّل التحقق بخطوتين على GitHub وRender وSupabase، واجعل المستودع Private، ولا تنشر المفاتيح، وخذ نسخاً احتياطية من Supabase، وأجرِ فحص اختراق قبل الإطلاق الواسع. إن تعطّل التطبيق بسبب سياسة CSP أضف `NO_CSP=1` مؤقتاً وأخبرني.
